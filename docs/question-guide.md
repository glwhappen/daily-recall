# 出题规范

题库是这个项目的主体。以下规则不是风格偏好，而是数据质量的前提——**一道坏题会污染整个统计链路**，而且是静默的、事后无法清理的。

## 一、一条好题的三个特征

1. **隔几天再问一次仍然有意义。** 这是最重要的筛选条件。如果一道题第 3 天问已经没有意义（比如「你今晚打算几点睡」），它就不能进 `offsets` 里的大数值。
2. **答案能在「记得」和「不记得」之间二分。** 题目的价值不在于你选了什么，而在于你**有没有能力选出一个**。
3. **能当锚点用。** 最好的题目自带外部线索（天气、地点、钱、和谁在一起），答完之后，当天的其他记忆会跟着浮上来。

## 二、三条硬规则（测试强制）

### 1. 选项必须穷举且互斥，用户永远不需要打字

```
✅ 昨天午饭你是怎么解决的？
   外卖 / 自己做 / 出去吃 / 没吃 / 不记得

❌ 昨天你吃了什么？
   （要用户打字 = 有门槛 = 不会坚持用）
```

「穷举」意味着所有可能情况都要有对应选项。写题时问自己：**有没有哪种真实情况落不进任何一个选项？** 如果有，选项就是不完备的。

「互斥」意味着不能同时选两个。反例：`在家 / 出门了` —— 下午出门了、但一天大部分时间在家，两个都对。这时要么改成 `你大部分时间在哪？`，要么加 `主要在家，中间出去过` 这样的中间项。

### 2. 每道 fact 题必须有一个 `kind: forgot` 的选项

```yaml
options:
  - { value: 点了, kind: fact }
  - { value: 没点, kind: fact }
  - { value: 不记得, kind: forgot }   # 必须有
```

理由：**没有出口，人就会瞎猜**。瞎猜产生的「假记得」会同时污染覆盖率、跨天校验和所有趋势图，而且事后无法识别哪些是猜的。诚实的「不记得」比虚假的「记得」有价值得多。

最多只能有一个 `forgot` 选项，且 `recall` 型题目不应包含 `fact` 选项（测试会拦）。

### 3. ID 与语言无关，且永久稳定

```yaml
- id: food-breakfast-takeout
```

- 用 kebab-case，`{分类}-{主题}-{区分词}`。
- **翻译或改写题干时绝不改 ID。** ID 是跨天校验的关联键：改了 ID，同一天的历史记录就再也对不上了。
- ID 一旦发布，视为不可变。题目要废弃时，从题库删除即可，不要复用 ID。

## 三、`fact` 还是 `recall`

| 类型 | 用途 | 选项要求 | 例子 |
|---|---|---|---|
| `fact` | 有客观答案，既能测记忆，也能当天的事实记录 | 2 个以上事实选项 + 一个 `forgot` | `{日期}你出门了吗？` |
| `recall` | 只能自评的题（「你还记得……吗」） | `记得`（`recalled`）+ `想不起来`（`forgot`） | `你还记得{日期}午饭吃的是什么吗？` |

`fact` 题的价值更高：积累几个月后，它们本身就是一份自动日记。所以题库里 `fact` 应占多数（当前约 2:1）。

## 四、`offsets` 怎么定

`offsets` 是一道题**适合在距今多少天时被提问**的列表。一次练习会从这些偏移里挑一个。

```yaml
offsets: [1, 2, 7, 14]      # 日常题目：近期多次问，逐步拉远
offsets: [1, 2, 7]          # 只对近期有意义的（几点睡、心情）
offsets: [1, 2, 3, 7, 14, 30]  # 长期有效的（出过门、花过钱）
```

规则：

- **必须包含 1**（测试强制）。任何题都应该能在「昨天」被问到。
- 数值越大代表拉得越远。同一个目标日期会在不同偏移上被重复问到，这正是跨天校验的数据来源——不是重复提问，是**有意的间隔重复**。
- 不要为了凑数加没有意义的偏移。如果第 30 天问「你昨天几点睡的」很荒谬，就别写 30。

## 五、`{日期}` 占位符

题干里的 `{日期}` 会在运行时被替换成「昨天」「前天」「一周前」等。

```yaml
text: "{日期}早上你点外卖了吗？"        # ✅
text: "昨天早上你点外卖了吗？"          # ❌ 写死了，隔几天再问就变成假话
```

## 六、六种典型的坏题

| 反例 | 为什么不行 | 怎么改 |
|---|---|---|
| `昨天你吃了什么？` | 开放题，要打字 | 改成 `recall`：`你还记得{日期}午饭吃的是什么吗？` |
| `{日期}你中午点外卖了吗，吃了多久，花了多少钱？` | 一次问三件事，答「不记得」时无法归因 | 拆成三道题 |
| `你是不是又熬夜了？` | 带评判和暗示，答的人会防御 | `{日期}你几点睡的？` |
| `{日期}你呼吸了吗？` | 答案恒为「有」，无区分度 | 删掉 |
| `{日期}你走了多少步？` | 需要精确数值，没人记得住 | `{日期}你活动过身体吗（走路也算）？` |
| `{日期}你在家吗？` | 与「出门了」不互斥 | `{日期}你大部分时间在哪里？` |

另外两条经验：

- **情绪类题目要克制。** `你有没有特别着急或焦虑的时候？` 这类题对有些人是有负担的。情绪类目（`mood`）应当可以整类关闭，且不要写成审判式的问法。
- **不要依赖精确时间或数字。** 人类对「几点」「几分钟」的记忆本来就差，这类题测的是时间估计能力，不是回忆能力。用区间选项（`6到8点`）而不是填数字。

## 七、`offsets` 与记忆类型

不同记忆的衰减速度差得很远，写 `offsets` 前先想清楚这道题属于哪一类：

| 记忆类型 | 衰减速度 | 合适的 offsets | 例子 |
|---|---|---|---|
| 事件（发生过的动作） | 慢 | 1, 2, 3, 7, 14, 30 | 出过门、见过人、花过钱 |
| 状态（持续的事实） | 慢 | 1, 2, 7, 14 | 大部分时间在哪、和谁待着 |
| 估计（时长/次数/时刻） | 很快 | 1, 2 | 屏幕前待多久、刷手机多久 |
| 细节（颜色/顺序/具体内容） | 很快 | 1, 2, 7 | 上衣颜色、午饭和晚饭哪顿更饱 |

给「估计型」或「细节型」的题配上 14、30 这样的远期偏移，结果就是用户一路点「不记得」——
那不是他的记忆差，是题问得不合理，而且会污染分档覆盖率，让远期那一档永远失真。

反过来，事件型题如果只写 `[1]`，就永远得不到「远期还记得」的正面数据，同样浪费。

## 八、提交清单

加题前逐条确认：

- [ ] `id` 唯一、kebab-case、与语言无关
- [ ] 题干包含且只包含一个 `{日期}`，且以 `？` 结尾
- [ ] 选项穷举、互斥、无首尾空格
- [ ] `fact` 题有且只有一个 `kind: forgot`
- [ ] `offsets` 包含 1，且每个数值都说得通
- [ ] 分类是 `categories` 里已声明的
- [ ] `npm test` 通过

你的题会隔几天、几周重新出现在用户面前。写的时候可以想一下：**一个月后看到这句话，我还能答得出来吗？**
